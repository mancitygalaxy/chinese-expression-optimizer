# 业务文档改写示例

以下均为构造的示例。原文展示了改写所需的全部信息，改写只调整表达。

## 示例一：减少翻译腔

原文：

```markdown
我们正在对导出功能进行测试，计划在周五进行配置调整。
```

改写：

```markdown
我们正在测试导出功能，计划在周五调整配置。
```

原因：句子更直接，“正在”和“计划”表达的当前状态与未来安排仍然保留。“进行”可以在合适的语境里使用，这里只去掉冗长搭配。

## 示例二：先讲动作和结果

原文：

```markdown
系统通过任务流转机制，把待处理事项分配给对应负责人，并跟踪处理结果，确保每个问题都有明确结论。
```

改写：

```markdown
系统把待处理事项分配给对应负责人，并跟踪处理结果，确保每个问题都有明确结论。
```

原因：分配事项、跟踪结果和明确结论都来自原文。改写删掉了重复的概括，让读者直接看到动作；如果原文只有“实现业务闭环”，应提示补充细节，不能自行补出负责人或处理方式。

## 示例三：少用不必要英文

原文：

```markdown
我会先同步 current status，再给 recommendation。
```

改写：

```markdown
我会先同步当前情况，再给建议。
```

原因：这里的英文没有增加精度，反而打断阅读。

## 示例四：去掉无依据的夸饰，保留目标

原文：

```markdown
这套方案计划将检索结果和原文放在同一页，目标是实现查阅效率的跨越式提升。当前仍处于设计阶段，尚未试用。
```

改写：

```markdown
这套方案计划将检索结果和原文放在同一页，以提高查阅效率。当前仍处于设计阶段，尚未试用。
```

原因：删除没有材料支撑的“跨越式”，保留提高效率的目标、设计阶段和未试用的状态。原文没有提供实测数据，改写不声称已经提高效率。
