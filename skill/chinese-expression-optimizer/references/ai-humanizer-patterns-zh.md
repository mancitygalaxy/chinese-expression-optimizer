# 中文 AI 味审校清单

用于用户明确要求去 AI 味、去套话或减少翻译腔时。目标是解决可观察的表达问题，不判断作者身份，不以 AI 检测分数验收。

先遵守 `SKILL.md` 的编辑取舍。下列词语和句式是检查线索，不是禁用表；按含义、读者和文体判断。已经自然、准确的表达可以保留。

## 常见问题与保留边界

| 现象 | 何时值得改 | 如何处理及应保留的内容 |
|---|---|---|
| “重要一步”“开启新篇章”等意义拔高 | 只有赞美，没有独立信息 | 删掉重复赞美，保留实际变化、作者判断和依据；不补造效果 |
| “跨越式提升”“革命性改变”等宣传夸饰 | 没有材料支撑程度，用户要求去套话 | 去掉夸张程度，保留原有目标和实际主张；已有数字及其条件照原文保留，不另换“大幅”“显著” |
| “赋能”“闭环”“全链路”等抽象词 | 读者看不出原文实际说了什么 | 用原文已有的动作和对象解释；技术意义准确的“闭环反馈”等可保留 |
| “进一步加强”“持续推进”等公文表达 | 空泛重复或掩盖责任和动作 | 直接说明原文已知的安排；原文没说谁负责，不自行指定 |
| 术语或长定语连续堆叠 | 需要反复回看才能理解 | 调整语序或拆句，保持修饰范围、归因和先后关系 |
| 机械开场、连接词与总结 | 只复述标题或前文，没有推进 | 合并重复；保留真正表达因果、顺序、转折和时间背景的连接词 |
| 强凑三点或整齐排比 | 项目同义、空泛或只是凑数 | 合并重复；三个独立功能、三项约束及有意的文学排比都可以保留 |
| “说实话”“坦白讲”等开场 | 只是套壳，后面没有对应态度 | 可去掉空开场；保留作者已有的犹豫、坦诚和情绪 |
| 客服式收尾与礼貌话 | 与当前交付无关、重复或机械 | 工作结果可直接结束；邮件、书信及关系沟通中的感谢与问候按用途保留 |
| “不是……而是……”式对比 | 引入原文无需讨论的虚假对立 | 直接说明观点；真实纠正、能力边界和否定关系必须保留 |
| 过度加粗、标题或短句 | 简单内容被切碎，阅读不连贯 | 恢复合适段落；保留帮助定位的信息结构，不规定固定段数或句长 |

## 按文体调整

正式工作稿需要清楚、准确，个人文章可以有铺垫、停顿、情绪和修辞。“结论先行”“补下一步”“说明验收方式”只在当前文档确实需要时使用；不能为了去套话给随笔添加行动计划，或把长篇思考压成摘要。

“更像真人”不等于增加第一人称、俚语、口头禅、错别字或亲身经历。没有作者样稿时，先保留原稿语气。有样稿时参考表达方式，遵循[样稿与文风校准](style-calibration.md)。

## 例子

以下原文包含全部已知信息，无其他事实前提。

原文：

> 这次更新新增搜索和导出功能，充分彰显了团队的创新能力。离线编辑计划下月测试，目前尚未开放。

改写：

> 这次更新新增搜索和导出功能。离线编辑计划下月测试，目前尚未开放。

赞美可删，功能、未来计划和开放状态均保留。不从“新增搜索”推断搜索更快，也不把“计划测试”改成下月正式推出。

原文：

> 我原以为写完就会轻松些。真写完了，倒有点舍不得。说实话，我也没想好要不要发出去。

可以保留。“说实话”在这里连接真实犹豫，叙述也有推进；改成“当前已完成写作，下一步评估发布”会失去作者声音。

## 交付

只审校时，指出实际问题并给必要的替换建议。直接改稿时，按用户需要给终稿，有重要疑点再说明。复查独立信息、推理、例子、限定与语气，不把“所有可疑词都删掉”当成完成标准。
